## 1. 目录回顶与扫描

### 已证实的原因

原 `settledScreen()` 将画面连续稳定与整屏行信息完整绑定，`toTop()` 因此会在有残行的回顶过程中中止。普通目录本来就不依赖锁、已购或勾选框状态；这些节点未命中不能解释本次故障。旧现场没有指出具体哪一行缺失，因此不能宣称已经定位了手机上的那条异常行。

[普通目录原始节点记录](D:/SoftWare/Project/android/blb/docs/evidence/v7-directory-tail-user-dump.txt:53) 已证明普通目录存在位于列表外的 `goto_top`。修复使用这个真实 ID，没有通过箭头外观或坐标猜测点击目标。

### 修改内容与代码位置

- [CatalogScanner：页面采集](D:/SoftWare/Project/android/blb/app/src/main/java/com/example/blb/auto/CatalogScanner.java:606)：分开检查页面、快照稳定与行完整性；保留列表直接子项顺序及残缺占位。分节和章节依据已取证的容器结构分类，无编号正文、总结或番外不按名称排除。
- [CatalogScanner：稳定等待](D:/SoftWare/Project/android/blb/app/src/main/java/com/example/blb/auto/CatalogScanner.java:752)：允许有界等待及重采样；错误页面、空树、多列表、没有可靠锚点、超时或无进展不能成为完整证据。恢复只保留实际观察，不把多个残行字段拼成完整行。
- [CatalogScanner：回顶](D:/SoftWare/Project/android/blb/app/src/main/java/com/example/blb/auto/CatalogScanner.java:1123)：限定当前目标页面和唯一可见的真实按钮，记录命中 ID、坐标、点击结果及滚动次数；按钮缺失时只反向滚动已确认的目录列表。点击或手势完成本身不证明到顶，仍需独立的列表边界探测及前后稳定内容。
- [CatalogSync](D:/SoftWare/Project/android/blb/app/src/main/java/com/example/blb/auto/CatalogSync.java:102)：保留“普通目录 → 下载／选择章节页 → 逐位置对照 → 回顶核实 → 事务写入”。首行允许是分节或无编号章节，不要求“第1章”；再次回顶核对实际建立的首行。
- [状态冲突与重扫](D:/SoftWare/Project/android/blb/app/src/main/java/com/example/blb/auto/CatalogSync.java:274)：已见锁、下载或可选状态不能在补全残行时被遗忘；等待、空树或重扫也不能清除已确认的冲突。既有 `gapNote`、`truncated`、`unresolved`、`trustworthy()` 仍约束正式目录提交。

## 2. 订阅明细与核对重试

### 已证实的原因

[运行日志](D:/SoftWare/Project/android/blb/运行日志.txt:50) 显示 w9899 聚合为20章，明细读到6条后因“列表总项数改变”退出，随后继续处理了其他账号。问题是逐章读取失败，不是没有遍历8个账号。

旧日志仅记录旧集合项数15，没有记录新值。“15→20”是本轮合成测试输入，不是已确认的真机变化。原代码将集合元数据变化直接判为失败，未利用交易身份、顺序及重叠事实判断是否仍是同一份清单。

### 修改内容与代码位置

- [SubscribedDetail：实际证据入口](D:/SoftWare/Project/android/blb/app/src/main/java/com/example/blb/auto/SubscribedDetail.java:742)：核对按钮使用的 `readWithEvidence(..., expectedChapters)` 已接入本次聚合章数；修改了实际采集链路。
- [SubscriptionAuditQueue：首次读取与重试](D:/SoftWare/Project/android/blb/app/src/main/java/com/example/blb/auto/SubscriptionAuditQueue.java:233)：首次不完整后重新定位聚合行、读取新聚合，并从首端独立重读一次。两次残缺结果不混拼，仍失败则记该账号未核实并继续其他账号；取消、全局故障及火券仍沿原规则处理。
- [SubscribedDetail：连续采集](D:/SoftWare/Project/android/blb/app/src/main/java/com/example/blb/auto/SubscribedDetail.java:1335)：集合项数与交易条数分开。项数增长须有一致的交易重叠；计数下降、索引漂移、重排、同数换交易、事实冲突或未知项都不能签完整凭证。首末端、连续位置覆盖、事实完整与可信聚合必须同时成立。
- [StepRunner：明细滚动](D:/SoftWare/Project/android/blb/app/src/main/java/com/example/blb/auto/StepRunner.java:666)：手势限定唯一目标明细列表，区分手势完成与容器方向探测。达到 expected、看到元数据末项或返回 false 都不能单独证明末端；首端探测不使用会触发下拉刷新的反向手势。
- 日期分组必须通过连续索引区间证明。零面积或不可读组头阻断日期传递，GONE 残留文本不作为日期来源。日期行和明确装饰行不算交易，未知行不会被历史覆盖数抹掉。
- 同一索引的每份已知观察都用于冲突核验，但完整交易只取某一次真实观察，不把金额与日期分别来自两张残屏的内容拼成完整记录。真实重复交易不会被全局去重隐藏。
- [逐章日志](D:/SoftWare/Project/android/blb/app/src/main/java/com/example/blb/auto/SubscriptionAuditQueue.java:391) 显示卷名、卷内印刷号、全书位置号、标题、金额、币种及日期。映射不唯一不补记，其他账号真实订过同一章的历史仍保留。
- [删前复读](D:/SoftWare/Project/android/blb/app/src/main/java/com/example/blb/auto/SubscriptionAuditQueue.java:321) 使用自己的新聚合；失败重试不替代删除要求的第二份完整一致证据。[RemoteLedgerRepair](D:/SoftWare/Project/android/blb/app/src/main/java/com/example/blb/auto/RemoteLedgerRepair.java:81) 也会拒绝读取过程中出现的火券证据，即使最终保留行只有代券。
