# v1.1 第十轮：作者没写章名的章节、跑完没有提示

现场：`v1.1第七次修复/blb-log-失败..txt` + 用户截图（目录列表里「星彩」卷下「第24章」确实没有标题）。

## 1. 「这一章本来就没有标题」把整趟跑挂了

日志 195/265 行：`未读全=1 … 列表第 2 项「星彩 第24章」缺少 章节身份`；200 行：`星彩 · 卷内第24章
→ 全书位置未能唯一映射`。截图证明那一章**作者没写章名**，不是我们读漏了。

代码里有**四处**闸门一起把这条明细判死：`SubscribedDetail.Entry.hasChapterIdentity()` 要求标题非空；
`RemoteLedgerRecovery.plan()` 与 `resolveAll()` 见到空标题直接判死；`resolve()` 里空标题 `continue`
让候选为空；`SubscribedDetail` 又把「有章号但空标题」的记录推去 `identifyUnnumbered`（必返回 null）。
后果：该账号「本账号保持未核实」→ 属于 MONEY_UNCLEAR（全局）→ **整趟「跑今天的整套流程」停在这里**。

**改法**

1. 「卷名 + 印刷章号 + 空标题」算**有效身份**；卷名读不到、或既无章号又无标题 → 仍然算缺身份（护栏不放宽，有用例钉住）。
2. 账本侧：目录扫描把这一行存成 `chapter.title="第24章"`、`volumeTitle="星彩"`，所以新增
   `RemoteLedgerRecovery.blankTitleMatches()` —— **卷名相等 + `Texts.rowChapterNo(chapter.title) == entry.chapterNo`，
   且必须唯一命中**（同号不同卷不会误配）。
3. 文案如实：`describe()` 打「（作者没写章名）」；`missingFacts()` 在缺卷名时说「卷名（作者没写章名时靠它定位）」；
   `resolutionFailure()` 单列「这一章作者没写章名，按「卷名＋印刷章号」也没能在本地目录里唯一定位…」。
4. 实施过程中第一版判据写错了一次（直接用 `!hasChapterIdentity()`，把「整行原文当标题」的番外写法一起拦了），
   被既有用例 `unnumberedExtraUsesTheExplicitVolumeAndFullTitleWithoutInventingANumber` 抓住后改正。

## 2. 跑完还是没有任何提示

队列运行时前台是 `com.sfacg`，我们自己的 App 不在前台 → 上一轮的「应用内对话框」根本不会触发 →
每次都走依赖 MIUI「后台弹出界面」权限的浮动弹窗；权限没给就什么都没有。而「跑完了」那条通知走的是
`IMPORTANCE_LOW` 频道（频道重要性 App 自己改不了），所以也不会弹横幅。

**改法（四条，已有的两条路都保留）**

1. 新增 `blb_done` 频道（`IMPORTANCE_HIGH` + 震动），结论改发它（标题＝`RunReport.title`、折叠态＝正文前 3 行、
   展开＝全文）；进度与停止仍走原来的低重要性频道。`ensureChannel` 改成两条频道各自判断 ——
   以前「第一条在就 return」，第二条永远建不出来。
2. **走了哪条提示路写进运行日志**：`完成提示：应用内对话框` / `完成提示：浮动弹窗（应用不在前台）` /
   `完成提示：浮动弹窗被系统拒绝，已发通知`。下次导出的日志一眼就能看出为什么没弹。
3. `AutomationService.onCreate` 补挂 `AppForeground.attach(...)`（幂等）—— 进程只被服务拉起时
   （例如开机后的定时那趟）`MainActivity` 从没跑过，回调也就没挂上。
4. 浮动弹窗 `startActivity` 抛异常时**补发高重要性通知**（不再只记一行日志）；应用内那步失败同样往下降级。
5. 判据抽成纯函数 `AppForeground.delivery(foreground, hostUsable, inAppShown, floatingStarted)` + JVM 用例。
