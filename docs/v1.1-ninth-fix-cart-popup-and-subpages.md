# v1.1 第九轮：订阅购物车残留、完成提示弹不出来、次级菜单 UI

用户报了三条（现场材料在 `v1.1第六次修复/`）。三条都已修完并验证。

## 1. 代券明明够却换号了 —— 购物车里的勾没清掉

**不是余额判据错。** 用户给的两份 dump 对照正好证明判据是对的：
`blb-dump-代券足够..txt`（已选 1 章 / 账户余额 0火券**33代券** / `tvTips` 实付0火券+11代券，**没有**「余额不足」节点）
vs `blb-dump-代券不足..txt`（代券 **9** / 出现 `tvChargeTips`「余额不足，快去充值吧」+ `tvCharge`「去充值」）。

真因在运行日志 `blb-log-订阅..txt` 第 180–190 行：皓平订到第111章之后，紧接着点第112章变成
「已选 2 章」，代码按安全规则（绝不一次买两章）拒买 → 换号；8 个号全部同一形状
（第 371/474/557/640/713/796 行）。**每个号一轮只订得到 1 章**，用户看到的就是「代券够却换号」。

为什么勾清不掉：`SubscribeTask.openChapterPicker` 见到页面上已有「已选」就**直接 return，根本没重进页面**；
买成之后代码也不离开页面。于是那一章的勾一直留着 —— 代码注释里那句「退出去再进来不保证清空」正是这个坑。

**改法**（`SubscribeTask` + `SubscribeRun`），每一步都读「已选 N 章」自证，绝不在不确定时点「立即下载」：

1. 买成后当场取消这一章的勾，**读「已选」确认**（买完那行可能已变「已下载」而没有勾，所以只信数字），
   结果写进日志：`第112章 买成后清勾：已选 0 章（清干净了）`。
2. 进页先读「已选」：0 → 照旧点目标行；>0 → 先按**上一章那一行**清（按标题重新定位，不用可能失效的旧节点）
   → 再读；还 >0 → `leave()` 真的退出去重进这一页 → 再读；仍不为 0 → **不买**，如实报告
   「上一章留下的勾清不掉……这一章这次没订，也没敢点『立即下载』—— 不是余额不足」。
3. 读不到「已选」(-1) 一律算不确定 → 不买、也不折腾页面。
4. 「点行之后必须正好 1 章」这条老规则抽成 `selectionIsExactlyTheTarget()`，语义一字未改。
5. 新增 `SelectedResidueTest`（9 条）：步进表全覆盖 + 「买单章仍必须已选==1」的边界。

## 2. 一个弹窗都看不到

**先更正一条**：上一轮我说「通知权限从来没申请过」是错的（当时 grep 用了 PowerShell 不支持的 `**` 写法）。
`MainActivity` 早就在申请 `POST_NOTIFICATIONS`。所以「什么都没弹」的真实原因只能是：
当初点过拒绝（系统之后不再弹框），或 MIUI 拦掉了后台启动界面。

**改法**：

- `ui/AppForeground.java`（新）：用 `ActivityLifecycleCallbacks` 记录前台状态；纯函数 `route(foreground, hostUsable)`
  决定「应用内弹窗」还是「浮动窗口」（界面正在结束、或前台那个界面就是浮动弹窗本身时，不算可用宿主）。
- `ui/DoneDialogActivity.java`：**App 在前台就在本 App 内弹** `AlertDialog`（同一份 `activity_done.xml`、同一个
  `RunReport`、同一个「看运行日志」入口），不依赖 MIUI 的后台弹窗权限；不在前台或应用内建不出来才退回原来的
  浮动 Activity（保留未删，锁屏显示也在）。渲染抽成共用 `bind()`。顺带修掉一个真 bug：队列在工作线程收尾，
  对话框必须在主线程建 —— 现在一律切主线程，失败再退回浮动窗口。
- `ui/DoneChime.java`（新）：响一声＋200ms 短震两条路共用（静音/震动模式只震不响；800ms 去重；失败只记日志）。
- 设置页新增两条可核对项：**通知权限**状态（绿=已允许/红=未允许）＋「打开本应用的通知设置」；
  **「后台弹出界面」**说明＋直达权限页的按钮（MIUI 两个入口逐个试，最后退回应用详情页）。
  查不到状态的只写说明，不假装能检测。
- 新增 `AppForegroundTest`（3 条）。

新增 4 个纯函数 + `EntrySummaryTest` +7 条（含一条「入口卡旧文案不许被顺手改掉」的回归断言）。
